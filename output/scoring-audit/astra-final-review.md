# Independent Astra final review — integration held

The candidate demonstrates useful capture-path work reduction and real CUDA overlap. **I do not approve the complete candidate for opt-in integration as shipped.** The claimed workspace bound is false for supported batched continuous scoring, final-consumer invalidation remains incomplete outside opportunity requests, and the purported competing-opportunity integration test bypasses the scheduler path it needs to validate. These are repairable issues, not evidence that the optimization approach should be abandoned. ARC parity failed the predeclared screen; neither matching throughput nor statistical equivalence is established.

This is the requested independent review, not implementation or a campaign restart. I read the supplied AGENTS instructions, applicable ancestor instructions, CURRENT.json, RESEARCH.md, initial diagnosis, frozen sources, patches, tests, protocols, analysis and raw evidence. I used only read-only inspection and small standard-library CPU parsing/hashing; I ran no tests, model, CUDA, PC, custody, installation or Git mutation. Only this report was written. No subagents were started. Findings below refer to the **packaged candidate**, not the intentionally unchanged Mac production source.

## Findings requiring action

### 1. High: the workspace charge omits the batch-scaled full scoring intermediate

[worker.py:1111](/Users/pippo/github/vllm-semantic-cache-ext/output/scoring-audit/results/scoring_audit/candidate/semantic_offload/worker.py:1111) charges retained unique backing storage, twice query bytes, three times field bytes, and an `R*K*(H+4)*4` allowance. But [index.py:85](/Users/pippo/github/vllm-semantic-cache-ext/output/scoring-audit/results/scoring_audit/candidate/semantic_offload/index.py:85) materializes `(query * means)` before reduction: its size is **R*K*H*D*4** for float32, where R is requests, K candidates, H KV heads and D head dimension. The charge has no corresponding R-scaled field term. Minmax and cuboid have additional full-size intermediates ([index.py:73](/Users/pippo/github/vllm-semantic-cache-ext/output/scoring-audit/results/scoring_audit/candidate/semantic_offload/index.py:73)). Continuous async still accepts these methods and batches.

A source-derived counterexample needs no GPU experiment: R=16, K=1024, H=8, D=128, distinct float32 mean storage. The code charges 17,694,720 bytes (~16.875 MiB), so a 64 MiB controller accepts it. The multiplication alone is 67,108,864 bytes (64 MiB); retained means + stacked means + multiplication already total 75,497,472 bytes (72 MiB), excluding query/output allocations. This is a false admission bound and can defeat the memory safety reason for opting into a bounded queue. It is not an assertion that the tested three-request/one-summary diagnostic exceeded its limit.

**Repair:** derive a conservative peak from actual method, batch, heads, dimension, dtype and simultaneously live intermediates, or bound/chunk the computation. Alternatively explicitly disallow the unsupported combinations until fixed. Keep the useful required-field projection and unique-storage accounting. The existing [test_audit.py:64](/Users/pippo/github/vllm-semantic-cache-ext/output/scoring-audit/results/scoring_audit/candidate/tests/test_audit.py:64) only checks projection, backing-storage inclusion and full-item-queue precheck; it does not prove a workspace upper bound. Separately document that the controller budget excludes the independently count-bounded opportunity snapshot bank, Python result objects and allocator caching; it is not a whole-process memory ceiling.

### 2. High: final-consumer residency and request identity protection is conditional, not universal

The new opportunity metadata carries scheduler residency tokens and hint IDs. That is a meaningful improvement. However, [worker.py:1433](/Users/pippo/github/vllm-semantic-cache-ext/output/scoring-audit/results/scoring_audit/candidate/semantic_offload/worker.py:1433) submits **continuous** async scoring without either token set. [worker.py:1240](/Users/pippo/github/vllm-semantic-cache-ext/output/scoring-audit/results/scoring_audit/candidate/semantic_offload/worker.py:1240) omits empty token fields from the emitted observation. [connector.py:9160](/Users/pippo/github/vllm-semantic-cache-ext/output/scoring-audit/results/scoring_audit/candidate/semantic_offload/connector.py:9160) checks residency only when the field exists.

Concrete sequence: finish a continuous score; pop its worker observation; evict and reinsert the same key at the ARC scheduler; deliver the observation before its time expiry. Its worker publication check already passed, and the scheduler has no old residency token to compare. The newly resident key can acquire the old observation's relevance. Current residency alone cannot distinguish these two residencies. The opportunity reinsertion test at [test_audit.py:79](/Users/pippo/github/vllm-semantic-cache-ext/output/scoring-audit/results/scoring_audit/candidate/tests/test_audit.py:79) explicitly supplies tokens, so it cannot expose this hole.

Request versions likewise stop at worker publication. They are present in the payload but absent from the emitted observation. `cancel_async_requests` prunes the worker-owned list, not an observation already returned by [worker.py:940](/Users/pippo/github/vllm-semantic-cache-ext/output/scoring-audit/results/scoring_audit/candidate/semantic_offload/worker.py:940). Continuous observations therefore also lack a final request-generation/cancellation check after transport. Opportunity hint retirement supplies a separate useful final gate, but does not establish a general async transport guarantee.

**Repair:** propagate and validate immutable residency and applicable source/request generation through the final consumer for every supported async route, or explicitly restrict promotion to the route with a complete contract. Add delayed-consumer cases, not just delayed executor cases. The same-ID test currently cancels at the next sampled `_on_queries_captured` callback ([worker.py:1315](/Users/pippo/github/vllm-semantic-cache-ext/output/scoring-audit/results/scoring_audit/candidate/semantic_offload/worker.py:1315)); it does not establish invalidation at request-start before the next stride sample, or after metadata has left the worker. Define and exercise that interval. No model run in this package establishes those adversarial lifecycle cases.

### 3. Medium: opportunity results can outlive the configured query lease

[worker.py:1356](/Users/pippo/github/vllm-semantic-cache-ext/output/scoring-audit/results/scoring_audit/candidate/semantic_offload/worker.py:1356) accepts an opportunity snapshot only within `_query_snapshot_max_age_ns`, but [worker.py:1169](/Users/pippo/github/vllm-semantic-cache-ext/output/scoring-audit/results/scoring_audit/candidate/semantic_offload/worker.py:1169) sets result expiry solely to capture time plus `_async_scoring_max_snapshot_age_ns`. The synchronous opportunity path instead uses query-snapshot age for expiry ([worker.py:1382](/Users/pippo/github/vllm-semantic-cache-ext/output/scoring-audit/results/scoring_audit/candidate/semantic_offload/worker.py:1382)).

With an allowed 100 ms query lease and 1000 ms async lease, a query submitted at 90 ms can publish at 200 ms and pass the async consumer expiry check. A longer-lived hint does not repair that contract mismatch. Defaults were equal in the measurements, so this does not explain the measured regression. **Repair:** carry the original applicable expiry, normally the minimum of query and async age limits for opportunity work, and test unequal settings. Do not refresh feature age when moving between stages.

### 4. Acceptance gap: the claimed competing-opportunity integration test runs the scheduler's continuous path

The ARC manager at [test_audit.py:16](/Users/pippo/github/vllm-semantic-cache-ext/output/scoring-audit/results/scoring_audit/candidate/tests/test_audit.py:16) is genuinely constructed and exercises native lookup/prepare/complete/eviction. CPU tensor scores are real. Those are stronger than fabricated score dictionaries. However:

- The scoring worker comes from `__new__` in [test_async_scoring.py:40](/Users/pippo/github/vllm-semantic-cache-ext/output/scoring-audit/results/scoring_audit/candidate/tests/test_async_scoring.py:40). The one constructor test patches native base initialization to a no-op and then shuts down; it does not drive scoring through that constructed worker.
- The scheduler helper uses `__new__` and a stub GPU pool ([test_step_1_5_prefetch.py:1248](/Users/pippo/github/vllm-semantic-cache-ext/output/scoring-audit/results/scoring_audit/candidate/tests/test_step_1_5_prefetch.py:1248)). The competing test [test_audit.py:108](/Users/pippo/github/vllm-semantic-cache-ext/output/scoring-audit/results/scoring_audit/candidate/tests/test_audit.py:108) never sets its `_scoring_schedule` to opportunity. `_retry_wait_prefetches` defaults missing schedule to continuous ([connector.py:2956](/Users/pippo/github/vllm-semantic-cache-ext/output/scoring-audit/results/scoring_audit/candidate/semantic_offload/connector.py:2956)).
- The test manually calls `receive_score_requests` with handcrafted versions/leases, drains synchronously, then invokes nomination. It bypasses scheduler request creation, metadata build/bind, bounded 50 ms deferral and fallback. Its final assertion proves some hint entered flight within capacity, not that the higher-scored exact prefix won.
- Connector consumption patches the base update method; retirement patches native completion. These are useful isolated contract tests, not full constructor-to-native-worker integration.

**Required CPU gate:** drive the actual opportunity scheduler branch through request metadata creation/binding, worker-produced scores and final selection with two constrained sources. Assert the exact winner, original timestamps, ordered EMA, unchanged ARC retention, timeout fallback and delayed-consumer rejection. Use real constructors where practical; name remaining seams accurately. This is especially important because **both product candidate runs submitted zero async score jobs**. A green count of 338 tests does not fill this missing path.

## Ownership and correctness assessment beyond the findings

**Producer/consumer readiness and lifetime:** required-field projection retains actual backing storage, including larger views. Query conversion creates an owned float32 tensor on the calling stream and records readiness; selected summary-job events replace a broad summary-tail fence. The controller synchronizes readiness off the caller thread, then the single scoring-stream owner stacks and scores. Payload references remain held through blocking `tolist()` completion; this is a defensible lifetime strategy without relying solely on readiness events or an ungrounded claim that `record_stream` is mandatory. The partial scorer exception path synchronizes that stream before releasing the payload. It does not turn a failed Python future into evidence of device completion by itself. CPU/fake-fence tests and the tiny fixture do not stress every partial-launch/allocator-reuse case, so I do not certify those from the test count alone.

**Tiny CUDA limitations:** [tiny.py](/Users/pippo/github/vllm-semantic-cache-ext/output/scoring-audit/results/scoring_audit/tiny.py) checks BF16 owned row selection, striding/GQA equality, source mutation, one opportunity score and final-source retention with real events. It uses the helper worker, default-stream summaries and an explicit producer-to-current-stream wait. It does not deliberately delay a score reader while recycling allocations, inject a partial GPU scoring failure, exercise consumer eviction/cancellation races, or run the real competing scheduler. Its 598,016-byte allocator peak is a fixture observation, not a proof of the general controller memory cap.

**Completion and leases:** empty retirement returns immediately; nonempty retirement uses ready-only publication. Reset/shutdown deliberately drain. This fixes the ordinary completion queue fence without deleting a useful final query. Snapshot storage is count bounded; age is checked at decision admission, and expired snapshots may remain allocated until another capture/cleanup, which is bounded retention rather than an immediate TTL-based free. Retired-ID bookkeeping tracks owned sources rather than every completed ID. The unequal-expiry and transported-generation gaps above remain.

**Cancellation/residency:** opportunity consumer checks actual pending hint IDs, matching source request IDs, hint expiry and current ready residency tokens; ARC prepare-store increments tokens and real reinsertion is covered. Worker publication also checks summary generation, immutable publication version and request version, rejecting entire nonfinite requests. These are real improvements. They do not cover tokenless continuous results or independently prove cancellation at every lifecycle boundary. The only production caller of `cancel_async_requests` found in this candidate is same-ID capture invalidation; tests directly invoking it are not evidence of an external abort-to-worker integration.

**Ordered EMA:** controller publication drains only an ordered ready prefix; one executor owns the stream. Request insertion order and per-request ranking feed the existing affine EMA composer. Drops/expiry deliberately change observation coverage; 1029 published diagnostic jobs and 13 pre-capture drops are not synchronous-history equivalence. The final consumer does not deduplicate observation sequences; sequence is logged rather than used as an acceptance watermark. Existing ordered-delivery assumptions may suffice for the normal transport, but duplicate-delivery resistance was requested and is not established. A CPU duplicate/reordering case should either verify the transport contract or motivate a generation-scoped watermark; do not silently promise idempotence.

**Unsupported configurations:** asynchronous TP restrictions and single dense KV group/preservation-event checks remain; opportunity async is limited to flat mean/mean TP1, while async indexed/capture-only combinations remain rejected. Full mixed CUDA graphs are rejected by capture preflight; the supported graph variants were not GPU-qualified here. All serving evidence is eager. Continuous async still allows the methods/batches implicated by finding 1; the error text saying scheduled scoring requires synchronous execution is also stale for the newly supported exception.

ARC correctly disables semantic capture/prefetch rather than doing artificial work for symmetry. ## Status deduplication and smallest next gates

The [status-only patch](/Users/pippo/github/vllm-semantic-cache-ext/output/scoring-audit/results/scoring_audit/postmatrix-status-only.patch) is a sensible, narrowly scoped followup: compare immutable scalar status fields, copy the last logged dictionary, emit transitions, keep metadata and other events. Its test preserves event delivery and checks 0→1→0 status transitions. I found no semantic-policy defect in this change. It removes repeated JSON/flush work, but still transports status metadata and does not deduplicate active event streams. Suppressing 1141/1178 identical idle status records (~396/409 KB) is concrete work removal; the effect on serving latency is unknown. It cannot retroactively turn the measured second pair into a pass.

1. **First, CPU/source gates:** repair the memory bound, final-consumer identity coverage and unequal TTL behavior (or explicitly narrow supported scope). Correct the opportunity integration test and trace-window analysis. Exercise exact winner, stale transport, same-ID before capture, cancellation, ordering and fallback. These do not justify another full model matrix by themselves.
2. **Then, one bounded CUDA correctness fixture** if the repaired allocation/ownership path needs it: delayed producer and reader, allocator pressure, partial-launch failure and budget recovery. Keep it tiny; the existing fixture leaves this exact ownership gap. No workload/admission/capacity expansion is recommended.
3. **Performance promotion requires fresh observer-off evidence for the final source.** After correctness, the smallest useful serving followup is a matched reversed ARC/final-candidate pair block (four short lifecycles), using the same workload/budgets and status dedup if retained. Keep common compact observers symmetric, preserve the failed historical block, and report arrivals/prompt work again. This is a minimal descriptive recheck, not enough to promise statistical equivalence. An observer-off GPU rerun is **not essential to accept the isolated logging patch as a correctness-preserving opt-in change**, but **is essential before claiming final-source throughput parity or promoting it on performance grounds**. Resource scheduling remains with the root/owner, not this report.

No additional large organic-competition benchmark is demanded merely to merge a corrected experimental opt-in. Until a separately justified constrained workload exists, explicitly withhold ranking-utility and organic async-throughput claims. Likewise, do not pursue kernel fusion, CPU mirrors or indexed search just to fill the missing attribution: the current evidence points first to lifecycle correctness and avoidable observer work.

## Explicit verdicts

- **Safe integration:** **hold the complete candidate as shipped**. Repair or restrict the identified supported-path defects, and pass the actual opportunity integration gate. The status-only deduplication is independently reasonable; it does not repair those defects.
- **Optimization coverage:** **substantial investigation and specific work reduction confirmed; “thoroughly optimized” is not justified**. Capture synchronization removal is demonstrated. Workspace guarantees and lifecycle coverage need repair, and executor/summary/competitive-path costs remain unmeasured. Deferring large-pool arithmetic work is reasonable within the tested small-pool scope.
- **Practical ARC parity:** **failed the declared screen; not established**. Never describe the two mixed pairs as a match, consistent speedup or statistical equivalence.
- **Remaining benchmark gaps:** final repaired/status source is unmeasured; no organic competing async decisions; incomplete executor CPU/readback and summary/D2H attribution; closed-loop work divergence; eager-only and tiny-fixture ownership limits. Correct existing analysis without GPU use, resolve CPU gates first, then request only the minimal justified shared-device followup through the existing owner.
