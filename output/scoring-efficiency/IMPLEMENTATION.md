# Scoring work reduction and indexed search

User authority: implement and measure the proposed work reduction and smarter candidate search, including missing component timings. Existing small-trial and minimal shared-GPU constraints persist. The eight-lifecycle design and finite custody duration are engineering choices, not user-imposed limits. No old paused campaign is resumed.

Measured production source is candidate v3 (candidate-pins.json). Default production behavior remains continuous flat scoring. All comparisons include the earlier Astra empty-nomination optimization; historical absolute values are not a matched baseline.

Opportunity mode samples attention queries at capture_stride8 into a detached, bounded per-request GPU snapshot cache (256 entries,1000ms max feature age). It performs no repeated block comparisons, readbacks, ranking or EMA updates during ordinary generation. The scheduler asks for eligible-source scores only when at least two DRAM-resident prefixes compete for insufficient staging room. All-fit and single-source decisions bypass ranking with explicitly unknown scores. Requested scores retain original query timestamp and expiry. Missing/stale observations permit the existing deterministic unscored fallback after at most50ms measured at scheduler boundaries; demand requests never wait for scores. This is an ARC shared-prefetch-only experiment and not semantic retention. Capture-only is a diagnostic control.

IVF mode clusters mean-key summaries on pool changes using four fixed initialization/assignment rounds (GPU reduction order need not be bitwise deterministic). Queries route by raw inner product to four of16 groups, then visited rows receive the existing exact mean-head score. Eight rotating exploration rows reduce permanent omission on a stable pool. Pools below128 use the original flat scoring path. Eligibility filtering happens before vector work when it makes the candidate set small. Candidate scores are exact on visited rows; shortlist selection is approximate and its local ranks alter rank-weighted EMA updates. Unvisited rows receive no score/freshness update. Index maintenance, routing, gather, readback and ranking costs all belong to this candidate. Exact native KV identity/prefix/ownership/completion fences are unchanged.

Component instrumentation is opt-in via SEMANTIC_PROFILE_DIR; files contain bounded counters, inclusive host wall/thread-CPU durations, log2 duration histograms and sampled CUDA-stream intervals. CUDA events are queried only when complete; no per-step synchronize is added. Scope nesting and interstream concurrency overlap, so totals cannot be added to explain elapsed time. Driver/runtime instrumentation is separately pinned on WSL. Observer-off product arms measure actual serving performance; profiled baseline/combined/capture-only controls diagnose work and instrumentation overhead. One trial per arm does not establish statistical significance.

Product matrix: ARC demand, continuous flat semantic, opportunity flat, continuous IVF, opportunity IVF (all observer off).
