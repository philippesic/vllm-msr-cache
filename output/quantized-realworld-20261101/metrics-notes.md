## Metric boundaries

- All rates divide by the full `load_start_ns`–`load_end_ns` interval, including think/idle time. Output tokens/s, completed requests/s, SLO requests/s, and SLO output tokens/s appear together. Failed or malformed rows do not become completed work. Planned request count mismatch invalidates a run; paired eligibility also requires a planned count, equal complete logical request sets, exact prompts/outputs/native key chains, valid native proofs, complete run status, and common nonempty corpus/model identities. Missing/duplicate logical IDs raise an alignment error. There are no output waivers.
- P50/P95/P99 are descriptive linear-interpolated empirical quantiles. TTFT and E2E include both intended-release and HTTP-submit origins. Release lateness includes pre-submit work and dispatch delay. Server queue time comes from terminal server timing. ITL uses one receipt timestamp per output token; multiple tokens received in one streamed chunk legitimately have zero receipt spacing. EOS returned by the endpoint counts as an output token.
- SLOs are investigator choices: chat release-TTFT ≤5s, per-request p95 receipt ITL ≤250ms, release-E2E ≤60s; agent ≤15s/500ms/120s (also per-request p95 ITL). A missing cohort SLO is unknown, not passed. These are finite-run goodput measurements, not a proven sustainable capacity frontier.
- Achieved server concurrency uses `postload_export.scheduler.counts`: `native_scheduler_calls`, `native_{running,waiting,scheduled}_{max,sum}`, and `native_{label}_hist_N`. Coverage must sum to all native scheduler calls for maxima/means to be accepted. Queued maps to native `waiting`. Histogram distribution is weighted without expanding a giant array. Legacy per-sample `running_requests`, `waiting_requests`, `scheduled_requests` are supported separately. Configured max_num_seqs never substitutes for an achieved value. Client in-flight includes server queue and is explicitly separate.
- CPU uses child process `/proc pid:start_ticks` identities and cumulative user+system time at the nearest available load boundaries. Missing process endpoints, malformed/reused identities, or missing CPU values yield null. Boundary overhang and sample span coverage are shown. The driver CPU/RSS fields are separate when available. RSS sums may double-count shared mappings. NVML is sampled device-wide; it can include display or other GPU activity. CUDA peaks are reset before load and exported after load, with per-worker peak sums explicitly labelled.
- Fields currently named `startup_*` report monitor samples before load only. Runtime starts the monitor after model initialization/warm-up, so these do **not** measure the full model-startup peak. Full startup peak is unavailable. The before-load CUDA snapshot and measured-load peak are separate. Short smoke sample coverage is incomplete at the first boundary and is reported, not silently repaired.
- Raw prefix numerical/capture counters and before/after deltas are separate. Missing baseline counters remain null unless the exact explicit-reset annotation authorizes sparse Counter zero semantics. Worker prefix deltas additionally require its baseline `metric_reset_scope` marker. This exception applies to counters only; missing CPU/memory measurements never become zero. Legacy audit numerical calls are preserved as raw after values where their pre-load origin cannot be established from the raw annotation.
- Wait-event timestamps use event-specific explicit fields (`decision_ns`, `submitted_at_ns`, `ready_at_ns`, `consumer_ns`, etc.), with timestamp coverage. No deadlines substitute for event execution timestamps. Transfers use unique job IDs/request IDs; success coverage and failures stay visible. Native adoption requires its proof dictionary to say same physical blocks and contain equal nonempty published/actual IDs. CPU resident bytes estimate uses sampled blocks × geometry block_bytes and is labelled an estimate; summary tensor storage is recorded separately.
- `performance_claim_eligible` is a conservative evidence gate, not acceptance of a performance win. The parent must still review budget comparability, repeated order/seed runs, offered-load sufficiency, latency effects, model qualification and broader scoring quality. Rates from failed/mismatched pairs remain descriptive only.

Retained own artifacts are small code/tests, this note, a hash receipt and the public smoke summary. Public datasets, prepared corpus and reusable model cache remain under their existing owners; no unrelated cleanup was performed.

## v3 offline staging usefulness and ownership

Current definition is `v3-p95-itl-offline-staging-utility`; request-goodput thresholds and v2 p95 semantics are unchanged. v3 fixes event timestamp coverage for native misses, request-owned staging, pending/final retirement, resume rejection and demand reclaim. Counters include both measured-window events and all recorded events; missing timestamps have their own type/ID inventory. Generic worker counter deltas expose the runtime hook's actual legacy numerical scoring call/query/scored-row counts, using the explicit-reset baseline rule.

`offline_staging_utility` joins chosen nomination event IDs to actual submitted jobs, readiness, request enqueue, first admission, native publication/adoption/miss, and final retirement. This is offline observed named-demand usefulness, not a policy input, task-quality measure, or credit for unspecified later reuse by other requests. Chosen decisions without a submission remain visible. Ready-before-enqueue and ready-before-first-admission are separate because queue time can make their conclusions differ.

Reservation lifetime is submission to native publication or final retirement. Request-owned lifetime begins at `staging_bound_request_owned` and ends at that same ownership transition. Pending-fence retirement does not end a live DMA reservation. Highwater sweeps actual reserved suffix block IDs over closed intervals clipped to the load window; sequential reuse does not add permanent capacity, and overlapping claims to one physical ID are reported. Missing cleanup/ambiguous intervals are unknown, with incomplete coverage explicitly reported rather than assuming release at load end.

Global readiness-completed traffic sums unique job IDs, separate from terminal-attributed consumption/waste. A native published prefix can combine already-local prefix blocks and a transferred suffix; only the suffix receives H2D/adoption byte credit. Published-but-missed and retired attempts remain visible. Completed-but-unconsumed bytes refer to the named demand; reservation `released_bytes` is capacity accounting, not transfer traffic. Conflicting/reused job identities invalidate aggregate byte credit rather than double-counting it.

Source inspection found that successful DMA finishing after lease expiry or pending-fence retirement emits final retirement without `staging_ready`. Old raw files therefore support a readiness-completed lower bound, not every completed speculative H2D byte. v3 supports the runtime owner's newly added passive `speculative_transfer_completions` collection, deduplicates per-job records, checks joins, and reports collection/attempt coverage and conflicts. Failed or missing completion evidence does not silently become successful zero-cost transfer. No old raw file was changed. New observer qualification remains runtime-owned.
