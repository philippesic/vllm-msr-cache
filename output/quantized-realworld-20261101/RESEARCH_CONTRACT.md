# Quantized real-world translation campaign

User authorization: set up and run more representative public workloads with a 4- or 8-bit model and higher concurrency, to roughly assess translation to real work. Prior no-commit/no-push and cleanup constraints persist. This is not authorization to claim general equivalence or production readiness.

## Mechanism and question

The current implementation stages exact known prefixes from CPU memory into a smaller statically allocated GPU KV pool. Lower device allocation comes from configuring that smaller pool at engine startup; eviction within an unchanged pool does not itself cudaFree device memory. Prefetch can hide demand H2D stalls when causal application waits overlap other GPU work. It does not compress KV, shrink weights, or guarantee more simultaneously decoding sessions. The matched ARC control already has CPU offload.

Question: on a larger truly quantized dense model, public conversation/agent content, and more active clients, can the system sustain useful request rates or resident/parked-session counts with less device memory and acceptable latency? What changes when no wait overlap exists?
