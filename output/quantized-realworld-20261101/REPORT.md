# Quantized public-workload translation test

The broader test does **not** establish a production plain win or the original within 1% matched-ARC goal. The candidate greatly improves on the original semantic configuration, and real prefetch works on public agent content after two private implementation changes. Smaller-cache ARC achieves the same memory reduction. Prefetch adds reservations, transfers, occasional preemption and latency risk.

**What reduces VRAM.** All arms use exact CPU KV offload. Configuring the GPU KV pool at engine startup to 1792 rather than 2688 MiB makes 896 MiB available. Ordinary eviction inside a fixed pool does not release CUDA allocation. Prefetch attempts to hide later CPU-to-GPU restoration during application waits; it does not compress weights or KV. The candidate's measured agent device footprint is about 865 MiB lower than large ARC, approximately 9.6% of that endpoint's observed NVML usage. Matched small ARC already saves this memory. This is a 33.3% smaller KV pool, not 40% less total VRAM or a guarantee of more active sessions.

**Test.** RTX 2080 Ti 11 GiB / WSL 16 GiB RAM, official Qwen2.5-7B-Instruct-AWQ 4-bit weights, FP16 activations/KV, actual Marlin quantized linear kernels, eager Triton V2/TP1. CPU KV cache 3.5 GiB in every arm. Public WildChat conversations and recorded mini-SWE-agent observations provide natural content; no pressure padding. Primary workloads use 36 distinct chat sessions and 72 distinct agent sessions across three paired corpus partitions. Each session has three actual-output turns, EOS respected, at most 96 generated tokens per turn. Later prompts contain this endpoint's generated outputs. Recorded agent observations are replay inputs, not tools executed from its generated commands.

Chat has 12 clients/up to 4 active requests and zero waits. Agent has 24 clients/up to 8 active requests and seeded 0/2/4/8/12 s waits. These arrivals/waits are simulated, not production timestamps. Hints expose only known completed prefixes and current pending-tool state, with a fixed 750 ms estimate; future text/deadlines and hint-ack gating are absent. All four arms run serially on the same host with rotated order. Results describe an instrumented endpoint with common proof/passive logging, not stock vLLM's maximum throughput. [Protocol and pins](CONFIRMATION_PLAN.json), [new agent protocol](AGENT_READMISSION_PLAN.json), [corpus provenance](corpus-notes.md).

Both burst workloads exceed investigator-chosen p95TTFT limits (5 s chat / 15 s agent) in all arms. They establish neither sustainable capacity nor session-count scaling. Agent candidate has 2 preemptions in one partition versus 0 in all controls; that partition's p95 TTFT 25.86 s versus small ARC 23.72 s. One candidate run has 29.4MB host swapout, retained and flagged. Driver CPU averages 1.42 s/chat and 4.05 s/agent for candidate versus 1.43 s / 3.47 s small ARC. Agent mean CUDA allocation 7.747 GB versus 7.739 GB small ARC / 8.678 GB large ARC; NVML 8.577/8.545/9.484 GB respectively. These are measured endpoint allocations, not extrapolations to a 32 GB 27B endpoint.

**Scoring and prefetch cost.** New agent candidate runs execute 53 numerical calls over 113 candidates, 27 budget-constrained nominations and 11 native adoptions. Completed speculative H2D totals 3.270 GB; intended requests consume 1.529 GB (46.8%). The remainder is unconsumed by the named demand, not proof of zero benefit to every other cache user. Request-owned suffix reservations peak at 447/367/590 blocks across partitions (up to 516 MiB of the fixed pool), reducing capacity available to other requests. Numerical cold-suffix mean scoring is meaningful active functionality, but differs from original per-block EMA.

The separate intrusive quality run transported 888 original-EMA observations and 2.685 million key updates, with fresh reference coverage on all 396 keys in its only actual multi-candidate staging decision. Candidate scores were unavailable at that decision, leaving **zero fully comparable decisions**: agreement is unknown, not 0% or preserved quality. Added all-cadence work changed opportunity timing; its performance is excluded. Neither ranking agreement nor model answer/task quality is established. Core numerical scoring and realized reuse above remain valid distinct observations.

**Bounded diagnostics.** All 296 requests across seven diagnostic runs passed strict proofs. Four agent clients abandoned causally in a 64-request-per-arm pair. Candidate throughput was 0.91% below small ARC, p95TTFT 20.36 versus 20.08 s, server CPU 77.81 versus 76.17 s; four native adoptions consumed 416.55 MB of 875.30 MB completed prefetch. None of the four abandoned clients actually had a staged transfer, so this does not qualify in-flight cancellation waste. Expired/other-retired traffic remains observed; no cancelled transfer was observed.

Finite first-turn open-loop probes used two fixed offered rates from ARC-only nominal calibration, 24 requests per arm and rate. Both arms passed chosen chat latency limits, with zero scoring/adoption. These are arrival-limited overhead controls, not maximum-throughput, prefetch-benefit or steady-state capacity evidence. Identical prompts still produced one/two output differences, making exact-work claims ineligible.

**Correctness and retained failures.** Primary passing evidence comprises 432 original-observer chat requests plus 864 new-observer agent requests, all strict-valid. The original 24-run matrix contained one failed physical-block proof after V2 preemption; its executor erroneously checked general run validity and continued. It remains failed, not repaired retrospectively. A common observer-only revision recognizes a full native readmission table only after a separately recorded new preemption episode, then runs the existing strict replacement validator. A new entire 12-run agent cohort, not a single selected retry, passed 864/864. 125 CPU checks and an actual 4-preemption qualification passed 24/24 strict proofs and 5.075 GB actual transfer-byte checks. Earlier shared-prefix qualification checked transferred bytes and local pages unchanged through native adoption; intrusive audits are performance-excluded and can mask races. Generated-output divergence remains unresolved; batch-sensitive quantized kernels are plausible, not proven causal. [Preflight](PREFLIGHT.md), [readmission qualification](runs/qualify-v2-readmission-public-agent640-v2/qualification-summary.json), [old proof failure](qualification/strict-proof-gap-terminal.json).

Other retained negatives: initial 7 GiB CPU cache caused paging; invalid typed wait hints did not dispatch; whole-prefix-only prefetch never scored on public shared-template traffic; suffix publication at arrival was evicted during queueing. Longer-wait experiments were cancelled before launch after identifying the structural shared-prefix guard. Private fixes support an exact shared GPU prefix plus staged cold suffix and publish at actual native lookup, with request ownership until lookup/cancel/finish. Both remain default off and restricted to the qualified dense TP1 layout. Canonical sources are unchanged; no commit or push.

**Recommendation.** Right-size ARC first. Keep the shared-prefix and lookup-publication prototypes for further development, with reservation/waste accounting and fail-closed preemption proofs. Do not enable them by default or advertise reduced total VRAM at unchanged throughput. A stronger next evaluation would use real application arrival/tool-duration traces, longer unconstrained completions and application/task success metrics on the intended production model/runtime; this test does not qualify the 27B hybrid architecture or predict its session capacity.
