# Useful negative evidence

These are screens, not confirmation runs. Prepared inputs, configuration, source/harness/runtime identities, complete raw requests and transfer events remain under `runs/`; raw JSON and server logs are losslessly compressed. `summaries.json` and `measurements.csv` are derived indexes. Historical results from other hosts are not controls for this experiment.

- **The original overhead goal was not robustly met.** The preceding `../scoring-overhead-20261101/REPORT.md` preserves the original and matched ARC comparisons, 22 repeated pairs, failed candidates, CPU and latency evidence. A pooled ordinary multi-session result inside 1% failed the per-pair check. Full-cadence scoring remained slower; the filtered-capture alternative changed score freshness. Those results are not relabelled as a successful global optimization.
- **Deduplication alone was insufficient.** Initial qualifying traces created repeated partial staging; the first native configuration had no native adoption. Exact-source refresh coalescing and complete-prefix-only admission were necessary. The technical qualification producer supplied a privileged post-pressure opportunity; later causal producers do not receive return deadlines or future prompt content.
- **Empty synchronous opportunity score containers crashed the first scored competing run.** Real ordered observations coexisted with empty legacy method dictionaries. The fix removes only empty method containers; conflicting nonempty representations remain rejected. The failed run and CPU regressions are retained.
- **The small 784-block long-context pool could not safely support the staged and live work.** One run stalled with completed legacy preemption-prefetch scratch occupying GPU capacity. The initial re-reservation-thrash hypothesis was wrong: the observed missing capacity was completed legacy scratch. Demand reclamation fixes the stall; a first reclamation version also missed a bound-hint protection condition, which review caught and the corrected lifecycle test covers. A completed trial still preempted three requests, lost complete physical proofs, and ran 7.21% behind large ARC. It is not a correctness-qualified capacity win.
- **CPU cache partitioning confounded the 4096-block long-context screen.** Matched small ARC evicted parts of a current warm source despite the current working set nominally fitting. The later DRAM screen uses 8192 CPU blocks for every arm and reruns controls. Its results are not pooled with the 4096-block runs. Short-context confirmation uses 2048 CPU blocks for every arm for the same reason.
- **Asynchronous block scoring was substantially worse on this host.** `dram-async8-1568` produced 5.681 output tokens/s versus 7.439 for large ARC, used 161.04 CPU seconds, and worsened return inter-token time to 88.7 ms. Post-load async work is recorded separately; startup timing does not explain the regression.
- **Sparse continuous scoring did not remove the fixed return cost.** Before transcript offload, stride32 reached 7.343 tokens/s versus 7.439 ARC, still 1.28% behind, with return TTFT about241 ms versus157 ms. A full-cadence diagnostic attributes only12.56 ms total to six native publication calls; publication was not the roughly84 ms per-return gap. Native reuse stopped at6144 tokens while ARC reused6160, forcing16 extra prompt tokens per return.
- **Prompt-only offload omitted computed generated KV.** Incremental offload plus an additional computed-transcript identity fixes that boundary. The final sampled token can be visible without computed KV; treating logical transcript length as computed length is a rejected control. Finished stores now cap by actual processed tokens, including in-flight subtraction. Source registration never bypasses CPU-store completion.
- **Restarted WSL invalidated two screen CPU measurements.** `psutil.create_time()` changed for the same live process as the boot-time wall-clock estimate moved. The original samples remain intact. The analyzer marks these costs unavailable rather than zero; all later runs use stable Linux process-start ticks. Monotonic request/load timing was unaffected. Confirmation requires valid CPU evidence.
- **Old opportunity scoring could perform no scoring at all.** With long tools, completed warm-source query snapshots expired; all-fit opportunities also bypassed ranking. The `transcript-opportunity-*` screens have zero applied scores and are explicitly ineligible, even where transfers and outputs were correct. The new prefix policy uses a common fresh active-peer query and separate validated scalar transport.
- **Decode-store audit positions needed repair.** Prompt-oriented positions clipped decode chunks to empty or reversed ranges. Source-store positions now use the actual offloadable transcript extent while prompt demand accounting remains prompt-only. Preservation-enabled CPU tests exercise exact commit ranges and completion consumption. Earlier snapshots remain recoverable.
- **Cadence alone has a quality cost.** After transcript reuse, stride16 was1.21% behind recent large ARC; stride32 at1536 blocks was0.92% behind in one screen but kept a roughly55 ms return-TTFT penalty. An optimistic common-resident-key hold-last proxy measured top10 overlap0.512/0.390/0.286 for strides8/16/32, with rank correlations0.733/0.634/0.536. This is neither EMA-policy quality nor reuse prediction accuracy. Sparse ranks are not presented as equivalent full-cadence scores.
- **A250 ms post-peer gap hid a real capacity limit.** Prefix scoring at1536 blocks achieved99.86% of large ARC in one screen with that gap. At zero gap, only3/6 returns adopted prefetched blocks, throughput fell1.93% behind large ARC, and return TTFT rose to474 ms. The1568-block candidate can hold the active peer and both prefixes; it is the zero-gap long-context confirmation candidate. No return request waits for hint acknowledgment.

CPU fixture/setup repairs are distinguished from candidate failures in their qualification directories: missing runtime overlay, duplicate CUDA-guard function identities, and incomplete `__new__` test fixtures. Passing CPU or numerical GPU checks alone never count as a throughput result.

## Final confirmation and bounded follow-ups

- The combined six short-context pairs remain 1.251% below large ARC and 0.121% below equal-budget ARC in pooled throughput. Four primary and two equal-budget individual pairs miss 99%; all are retained. The six long pairs pass the throughput threshold, but return TTFT still rises about 25 ms against large ARC. Neither performance workload forces competing semantic selection; their strict combined semantic-functionality flag remains false.
- Three separate scoring-quality diagnostics do force five comparable constrained choices. Raw-prefix/old-EMA winner agreement is only 2/5. Four unconstrained decisions have no raw score and are not counted. These instrumented runs are excluded from performance, even when a raw generic runner field says otherwise; plan provenance controls eligibility.
- Ordered gather is exact in 478 CPU tests and 16 packed-KV CUDA cases, but its screen is 0.32% slower than the frozen prefix baseline. Only a private frozen source contains it. It is not integrated.
- One ARC640 control in that gather screen diverges from output token two on request 16; eight other same-seed ARC controls and the other three arms agree. Prompt native keys match, but generated KV bytes/logits were not captured. The affected exact-output comparison is false and unresolved, with no retry or waiver. Neither numerical variation nor KV corruption is established. See `gather-screen-output-crossreference.json` and `output-divergence-review.md`.
- Public last-tool submission activation reduced hint RPCs 102 to 42 but did not improve throughput: -1.82%/-1.70% against fresh large/equal-budget ARC. Its fresh exactness checks pass. It is an alternative causal producer policy and may change scoring timestamps/query choice; it is not selected for confirmation.
- Current-prefix profiling attributes only 34.75 ms to summary construction per short run, approximately 0.14% of load time. Unrelated-source summary suppression risks missing later declared sources; source-finalization/backfill and deferred-store lifecycles remain unimplemented because the measured costs do not justify that scope. Detailed limits are in `summary-cost-recommendation.md`.
- The first quality launch selected the observer path but omitted `SEMANTIC_PREFIX_POLICY_QUALITY=1`; it produced no observer evidence and counts toward neither quality nor performance. The separately enabled three-seed diagnostic succeeds. `quality-setup-receipt.json` preserves the setup error.

Standalone native byte-copy qualification passes all 28 full packed K/V components, but is not an explanation for the isolated no-H2D ARC divergence or a model-serving throughput result.
