# Wait-hint staged qualification

Selected local execution across **all four stages is complete**. This is not a
declaration that all product gates passed. The user authorized staged execution
and routine diagnosis, with plain ARC as the primary comparator. Clear causal
and cache-pressure gains support continuing the mechanism; adverse and
inconclusive cases restrict its operating and adoption claims.

Completed evidence supports continuing work on CPU wait retention. It does not
support universal superiority, production reliability, or equal useful-answer
quality across systems. Workflow batch time is the primary metric. Percentages
below mean less batch time, not the reciprocal throughput increase. Intervals are
conditional 95% intervals over paired whole runs on fixed inputs, not a sampled
deployment population or a correction for every comparison in this campaign.

| Question | Completed finding | Scope and limitation |
| --- | --- | --- |
| Does the complete addition beat no-hint ARC? | Live original workload: 8.07% less time, interval 7.00–9.12% | Three pairs on one model/runtime/host; live outputs and paging differ |
| Is retention itself useful? | Full hints beat inactive hints by 7.66%, interval 5.28–9.97%; identical-token replay beats ARC by 4.72%, interval 3.12–6.30% | Replay is a diagnostic; trace chains support changed recency and later reuse without proving a counterfactual eviction |
| Does it compete with published systems? | Four-system original workload: 7.51% less time than ARC, interval 4.87–10.08%; 7.70% less than Continuum, interval 4.90–10.42% | Complete configured systems use different runtimes; this does not isolate policy superiority |
| Is it competitive with the upstream draft? | Separate six-pair confirmation: 0.60% overhead, interval −0.69 to +1.90%, within the declared 3% margin | No resolved lead. This is the pinned published retention draft plus a disclosed compatibility fix, not stock released vLLM |
| Do fresh repository tasks retain a benefit? | Revised-instruction reserve: 8.27% less time than ARC, interval 4.49–11.89%; 8.79% less than the upstream draft, interval 5.98–11.52% | Authored real-tool workflows in more-itertools; retained factual and missing-limitation errors |
| Do fresh document tasks retain a benefit? | Full-budget reserve: 18.12% less time than ARC, interval 16.55–19.65% | Real PEP tools and fixed returning workflows; no resolved upstream difference or general answer-quality equality |
| Where is the benefit unresolved? | Tight eight-sequence document reserve: 0.98% less time than ARC, interval −2.00 to +3.87% | Below the useful 2% point target; narrowly fails to establish the 2% neutral-overhead bound. Individual ARC losses are retained |
| Is a tight-document mitigation promising? | Preselected four-sequence diagnostic: 9.29% less time than ARC, interval 2.23–15.84% | Development evidence; no fresh qualification of that admission setting and no proof it always suffices |
| Does the graph-mode workflow retain a gain? | 8.87% less time than ARC, interval8.08–9.65% | All six timed graph paths verified; known answer-quality failures remain |
| Does the public bounded profile retain performance? | 4.28% less time, interval−0.75 to+9.07%; all pair points favorable | Within the 2% neutral-overhead bound; useful gain unresolved; cancellation/drain/recovery pass after timing |
| Does the 1.5B model establish a speed gain? | Full-budget 3.06%, interval−5.28 to+10.75%; constrained 4.67%, interval−1.18 to+10.17% | Neither establishes useful gain; constrained meets2% neutral bound, full-budget has no CPU-load opportunity; weak answers remain |

More CPU cache can remove ARC's eviction pressure and erase the retention
advantage. Several all-fit cells therefore show no meaningful benefit. Tight
GPU admission can interact with restores, preemptions and decode tails; observed
transfer volume alone is not a causal explanation. Negative and inconclusive
cells remain part of the result, including the initial ample-cache comparison
and its separately selected fixed confirmation. No tuning or pooling across
these confirmations is permitted.

These are conditional whole-run results with predeclared owner-selected margins,
not user-specified numerical requirements or a population-wide harmlessness proof.

The source audit currently covers 448 first-repetition final answers from the
independent families. Correct HTTP completion and correct metadata/test labels

limitations remain scored as failures. See [answer quality](QUALITY.md) and the

   identical-token replay, targeted removals and block-level trace evidence.

3. [Operating range](STAGE3.md): independent families, instruction calibration

4. [Compatibility and reliability](STAGE4.md): selected model/layout/execution
   cells, fresh-computation references, rejection/cancellation/recovery checks,
   minimal integration and isolated reproduction. All eight functional cells, both standalone clients and isolated installation/integration pass. All four selected workflow comparisons are complete; only graph-mode timing establishes the declared useful gain, while the other cells retain uncertainty and quality limits. The read-only runtime interface/constructor boundary has been measured.
