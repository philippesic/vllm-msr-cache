## Metrics, precision, quality and interpretation

Retain end-to-end measured workload seconds and completed graph units/second as
primary system metrics; report requests/second, output tokens/second, prompt and
output token counts, startup and total process time separately. Warmup/model
startup are excluded from serving duration but included in acquisition cost.
Units include short abandoned sessions in the interference cohort; they are not
equal useful work. Comparisons use identical offered units within each cohort.

For each fixed complete set, use paired whole-process log throughput ratios,
geometric means and two-sided 95% Student-t intervals (df=3, critical 3.1824463053
for four blocks; df=23, critical 2.0686576104 for 24 pairs). No request-level
pseudoreplication, optional stopping, run rejection for unfavorable timings or
multiple-comparison-adjusted winner claim. Report arithmetic mean/median seconds
and every pair alongside CIs. Four repetitions may have wide intervals. Incomplete
sets remain descriptive, with missing/failed blocks visible; no fixed precision
or noninferiority claim from incomplete acquisition. For QA, declare the 3% bound
met only if the interval lower limit is at least 0.97; an interval crossing it is
inconclusive, not proof of a regression. Original six-pair outcomes remain intact.

For prediction stress report accurate/ARC, misleading/ARC and misleading/accurate
ratios. Derive per-class mean and p95/p99 end-user first-token latency and request
completion latency, client queue, workflow and tool-to-first-token latency from
raw receipts. Compare unhinted whole-process mean latency with paired log-ratio
CIs and a 1.05 upper bound; show per-process p95/p99 descriptively. Only 16
unhinted requests/process (64 per arm total) makes p99 an unstable descriptive

counts; 16 QA units do not imply 50% resource share. Native loaded/computed tokens,

## Fixed budget, failure handling and unattended sequencing

Agent-proposed expected cost is 3–5 GPU hours, primarily fresh server startup;
this is an estimate, not a guarantee. Hard limits are **six elapsed hours overall,
two elapsed hours per section**, **85 total attempts**, and the section caps in
the table. Persist the first acquisition/section start times across recovery;
20-minute wakeup/recovery gaps consume these caps. Each worker keeps the existing
0.5s owned supervision, 900s startup bound, 900s addendum case bound and owned
cleanup; its invocation is additionally cut off by the remaining section/overall
budget. A section cap closes that section, retaining partial blocks, and permits
other sections within the overall budget. No budget extension is automatic.

At most one whole four-system repository block and one whole three-arm advice
block can replace a diagnosed setup/transport/owned-cleanup/tool-execution defect.
Keep original attempts and link the diagnosis with `repair`. No pressure-gate,
overhead-pair, performance or answer-quality replacement is allowed. Failed
requests, missing telemetry, ownership loss, inactive external policies, incomplete
graphs or unclean shutdown stop for diagnosis. Before resume verify actual GPU
and both locks free and no surviving owned worker. `--resume` marks interrupted
attempts and reuses only sealed complete whole blocks. If a section cannot be
repaired in scope, `close-section` preserves its evidence/reason and permits the
remaining sections; unresolved is never reported as passed.

Only post-acquisition scheduled wakeups launch/resume this coordinator, from its
attested source snapshot. It holds the common GPU reservation for the complete
invocation, including gaps. A bounded `status` reads persisted progress plus
